Frozen at the commit that adds this file on branch `quick-benchmarks` (2026-11-07). Later changes go into a new file, never
into this one (CLAUDE.md rule 7).

This file edits no frozen file: `hypotheses-round2.md`, the round-2 grid freeze 9d7e8fe, `design/review-runs/floor-rerun.md`
and the round 2 and round 3 records stay as they are. `design/review-runs/adversarial.md`, `ablations.md` and

stay unchanged as the record of the long design. Nothing here enters a frozen family or a hypothesis. Every result is
descriptive: median and spread (rule 4), no test, no interval over seed pairs, no Holm step.

Authority: Alex's approval of Q20261103-p2-2 ("P2-2: I approve the new runs") and his instruction of 2026-11-06 to use very
quick benchmarks (P2 `STATE.md`). The runs are the two needs-run lines of Papers `p2-typed-routing/writing/fixes-r4.md`
(Gemini r4 G9b, Grok r3 M3 and M5). Rule 5 sets the length: each campaign takes at most 10 minutes. Rule 1: Release builds
only, -O3 with Clang. Rule 3: the laptop only, one campaign and one OS at a time.

## What each run answers

- **(a) The worst case of the matcher's walk.** RegexMatcher v2 at d1d73e99b, unmodified, timed by the adversarial tool
  (`bench/tools/adversarial`, rbench's timing loop unchanged) on tables built so that every node on the query's path is a
  choice point and the query fails at the last segment (two kinds per node up to depth 16, four kinds up to depth 8, with and
  without a catch-all), beside the last-hit query of the same table, which matches and walks the same nodes. The backtrack
  counts come from the matcher's own code: the counting copy (`bench/tools/route_count.hpp`, v2's headers renamed with a
  counter on seven marked lines of the walk, checked against the pinned headers by `make_route_count.py --check`).
- **(b) One ablation arm per design choice, and the language-boundary arms.** Four variants of v2, each the renamed copy and
  one change, against the copy (the control) and the pinned arm; and the symmetric boundary arms at m = 10 and 100.

## Arms

| Arm | The one change from `regexmatcher-v2-copy` | Design choice |
|---|---|---|
| `regexmatcher-v2-ab-noexact` | every method counts as having a parameter route: no exact-match table | exact-match table |
| `regexmatcher-v2-ab-bytes` | edge labels compared a byte at a time, not as 8-byte words | 8-byte segment key |
| `regexmatcher-v2-ab-heapstack` | the walk's choice stack in a heap block, `new[]` at the start of every walk, `delete[]` at its end, instead of an array in the walk's frame | stack backtracking |
| `regexmatcher-v2-ab-strings` | a captured value owns a `std::string` copy of its bytes instead of a view into the path | string views |

- Each variant is generated by `bench/tools/make_ablation.py` from v2 at d1d73e99b; every added line carries the mark
  "ablation (<arm>)"; the script checks one hunk per anchored block (ab-strings has a second hunk, the include of
  `<string>`). The table of every variant but ab-noexact equals the pinned table field for field (`test_ablation`).
- `ab-strings` needs its own adapter (`arms/regexmatcher_v2_ab_strings.cpp`): the harness reads the captured values as
  views after the lookup returns, so the adapter keeps the last Match as a member and moves each answer into it. That move is
  part of the arm's time; an owning design pays it wherever the answer outlives the call. Its captured values are checked
  byte for byte and must not point into the path.
- `ab-heapstack`, `ab-strings` and `ab-bytes` change the lookup code (the objdump check finds them DIFFERENT from the copy);
  their time difference can come from code layout as well as from the change. Allocations per lookup are in each line.
- Boundary arms, as `design/review-runs/boundary-arms.md` defines them: `regexmatcher-v2-capi` (v2 behind its own
  `extern "C"` translation unit, the Rust arms' call shape), `capi-null`, `rust-null`, `regexmatcher-v2-goloop` (v2 called
  from a Go loop, labelled as including the Go-to-C call), beside `regexmatcher-v2`, `null`, `null-no405`, `matchit`,
  `actix-router`, `path-tree`, `gin`, `httprouter`, `chi`, `uwebsockets` and `glaze`.

## Not run, and why

- **Windows.** rbench builds on Linux x86-64 only (its CMake stops elsewhere; the core uses `x86intrin.h`,
  `perf_event_open`, `malloc_usable_size` and `unsigned __int128`), and the Go arms are c-archives that MSVC cannot link. The
  earlier lookup grid was Linux only. A port of the C++ path to MSVC is new work outside this plan. Windows stays a stated
  limit of both runs, so the A/A run is measured once, on Linux.
- **`nethttp`.** It is pinned to Go `go1.27.1-X:nodwarf5` (`cmake/pins.cmake`); the laptop's Arch has Go 1.27.3 in
  `~/opt/p2/go1.27.3` (journal, 2026-10-24) and no install of the pinned package is recorded. The other Go arms build with
  1.27.3; the paper states the version difference from round 2.
- **ab-linear and ab-hashed** (built and tested, not timed): the fix line names the four choices above.
- **The other-method queries** of the adversarial tool: their counts equal the miss queries' by design (`adversarial.md`).

## Design

Common: one process at a time on CPU 2 (`taskset`), rbench's defaults (21 epochs after one warm-up, at least 5 ms each, the
median ns per lookup over epochs, the ring of 4,096 queries) except where named. Every round runs every cell once; the order
is shuffled again in every round from the plan's order seed. Seeds are new: the first 8 hex digits of sha256 of a label
(`P2 quick order <plan>`, `P2 quick table <plan> round <r>`, `P2 quick ring <plan> round <r>`), checked against every seed
earlier runs used or froze (1 to 5, 110 to 126, 127, 210 to 226, 227, 20261009, 20261010, 20261103, 20261104). In an rbench
plan every process of a round uses that round's table seed and ring seed, so a round's arms see the same table and ring.
The plans are fully expanded in `bench/quick/plans/*.jsonl` (`quick_plans.py`), so the sha256 of a plan pins its rows,
order and arguments.

| Plan | Run | Arms | Cells | Processes per round | Rounds |
|---|---|---|---|---|---|
| quick-L-adv | (a) | the adversarial tool, ring 256, one table build | 33: 11 tables x miss and last-hit, 11 catch-all tables x miss | 33 | up to 3 |
| quick-L-abl-s | (b) | v2, null, copy and the four variants, and the A/A arm (v2 again, a second process) | 7 shapes x m = 10, 100 | 112 | 4 |
| quick-L-abl-l | (b) | copy and the four variants | 7 shapes x m = 10,000 | 35 | 3 |
| quick-L-bnd-10 | (b) | the 15 boundary-set arms | 7 shapes x m = 10 | 105 | 5 |
| quick-L-bnd-100 | (b) | the 15 boundary-set arms | 7 shapes x m = 100 | 105 | 5 |

The adversarial ring is 256 instead of 4,096 because its agreement pass checks every copy of the ring and dominated the
desktop planning run; `--build-reps 1` builds the table once instead of five times (only the reported build time changes).
Every query of the ring is the same, so the times are those of a learned walk; the counts are exact and do not depend on it.

## Runner and checks (`bench/quick/quick_run.py`)

Before anything is timed it refuses with exit 2 unless the plan's sha256 matches, HEAD is the job's commit, the plan's system
is this one, `compile_commands.json` shows every C and C++ file of `bench/` at -O3 and at no other level, and the untimed
correctness checks pass: every ctest of the build (the ablation answers on 112 tables, the copies against the pinned headers,
the objdump checks, the boundary call check, the adversarial unit test and self-test, the plan tests) and, for an rbench plan,
the agreement test of its arms on its shapes, sizes and table seeds judged by `check_agree.py` and every arm's probes. No
sanitizer runs on the laptop (rule 2), and the records gate of the earlier job scripts is not used. Then it runs the rows in
order and keeps every process (`units/<id>.json`, `units/<id>.err`, `job.json`). Before each round after the first it stops
when the time used plus the mean round would pass 600 s; before each process it stops when the time used plus that cell's
longest time so far (else the plan's estimate) would pass 600 s; a process still running at 600 s is stopped and kept with
exit -9. A failed process is not rerun. Exit 0 when every process exited 0, 3 otherwise (data kept).

## What is computed (descriptive, rule 4; the analysis is a later step on the Release archives)

- **(a)** Decided deterministically, per process: the counting copy's checks of the written bound (no node entered twice per
  walk, entries at most the trie's nodes, resumptions per node at most four, the copy's answer equal to the pinned code's,
  and the guards against a vacuous count). If any fails, the paper's code-read bound is wrong and the paper says so. Per
  cell: the node entries, the choice points pushed and popped (the backtracks), the deepest stack, each beside its bound;
  the median over rounds of the median ns per lookup with its minimum and maximum; the time per node entered; the miss
  query beside the last-hit query of the same table; the largest backtracks per query over all cells.
- **(b) Ablations.** Per cell and round, each variant's ns per lookup over the copy's, and the copy's over the pinned arm's
  (quick-L-abl-s); per cell the median over rounds with the minimum and maximum. Beside it: net instructions per lookup
  (net of `null` where the plan has it), branch misses and allocations per lookup, and each variant's normalized lookup
  code size from the build. An arm whose process in a round is not usable takes no part in that round's ratio, and is listed.
- **(b) Boundary.** Per cell and round: `regexmatcher-v2-capi` over each Rust arm and over the fastest of them; v2's net
  time over the fastest competitor's net time, each net of its own null (C++ arms of `null` or `null-no405` as the earlier
  campaign pairs them, capi of `capi-null`, Rust arms of `rust-null`, Go arms and goloop of their own Go null pass); goloop
  over each Go arm. A net time that is not positive is listed and left out, as `boundary-arms.md` states. Per cell the median
  over rounds with the minimum and maximum, raw times beside.
- **A/A.** Per cell and round of quick-L-abl-s, the A/A arm's ns per lookup over v2's, the same binary and arguments in a
  second process; median and spread over cells and rounds, reported once for Linux, never used to tune anything.

## Deviations from the long designs (the paper states each)

1. Rounds of one process per cell instead of 10 processes per cell (adversarial) or 16 seed pairs (grid); median and spread
   over rounds, no BCa interval.
2. New seeds per round; no round-2 seed pair is reused.
3. Two ablation choices were added (stack backtracking, string views) and two were not timed (linear and hashed edges).
4. The adversarial ring is 256 and its table is built once; the other-method queries are not run.
5. The ablation grid covers m = 10, 100 and 10,000, not 1,000 and 100,000.
6. No sanitizer records gate the jobs (rule 2); sanitizers ran on the desktop for correctness only.
7. Linux only; nethttp is not run; the Go arms use Go 1.27.3.

## Desktop verification (correctness only, nothing timed)

On the desktop's WSL with Clang 18.1.3: a Release build of the C++ arms, the Go arms (with the pinned Go of the desktop) and
uwebsockets, every ctest passed (14); the agreement test and the probes of every built arm passed; the runner's untimed checks
passed for quick-L-abl-s, quick-L-abl-l and quick-L-adv. ASan with UBSan: the C++ arms and the tool built, the ctests other
than the objdump checks passed, the agreement test passed, and short `--quick` cells of the new arms and of the tool ran with
no report. Not verifiable on the desktop: the Rust arms (no Rust in WSL), glaze (needs a newer Clang than 18), the Go arms
under ASan, and MSan (no instrumented libc++ for this build). The laptop job runs every ctest and the agreement test before
any timing, so a build or answer fault there stops the job with exit 2.
